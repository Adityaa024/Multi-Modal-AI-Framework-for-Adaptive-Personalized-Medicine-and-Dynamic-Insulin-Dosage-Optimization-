# A Multi-Modal AI Framework for Adaptive Insulin Dosage Optimization in Type 2 Diabetes Management

This repository contains a **research-grade FastAPI backend** for experimenting with adaptive insulin dosage optimization in Type 2 diabetes management.

The focus is on:
- **Clear modular architecture**
- **Separation between API, data, and ML layers**
- **Reproducibility and extensibility** for research.

> Note: The ML logic in this scaffold is intentionally simple and deterministic. It is designed to be a safe, pluggable baseline for experimentation, **not** a production-ready clinical decision support system.

## Project Structure

```text
app/
  api/
    routes/
      patients.py          # Patient registration & history endpoints
      predictions.py       # Insulin dose prediction endpoint
    deps.py                # Shared dependencies (DB session, etc.)
  core/
    config.py              # Core configuration (paths, constants)
  db/
    base.py                # SQLAlchemy Base import
    models.py              # ORM models for Patient & DoseHistory
    session.py             # DB engine and session factory
  schemas/
    patient.py             # Pydantic schemas for patients
    prediction.py          # Pydantic schemas for prediction IO
  services/
    ml/
      dose_model.py        # ML / heuristic layer for insulin dose
      preprocessing.py     # Input normalization & feature preparation
  main.py                  # FastAPI application entrypoint
```

## Getting Started

### 1. Create and activate a virtual environment (recommended)

```bash
python -m venv .venv

# On Windows (PowerShell)
.venv\Scripts\Activate.ps1

# On Linux/macOS
source .venv/bin/activate
```

### 2. Install dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Run the API

```bash
uvicorn app.main:app --reload
```

The API will be available at `http://127.0.0.1:8000`.

- Interactive docs (Swagger UI): `http://127.0.0.1:8000/docs`
- Alternative docs (ReDoc): `http://127.0.0.1:8000/redoc`

## Key Endpoints

- **Patient registration**
  - `POST /api/v1/patients/`
  - Registers a new patient with basic demographic and baseline clinical data.

- **Patient history**
  - `GET /api/v1/patients/{patient_id}/history`
  - Returns past insulin doses and associated glucose measurements for the patient.

- **Insulin dose prediction**
  - `POST /api/v1/predictions/insulin-dose`
  - Given patient metadata and recent glucose metrics, returns a *research-use-only* suggested insulin dose.

## Research Notes

- The current `services/ml/dose_model.py` implements a **transparent heuristic baseline**:
  - Uses recent glucose readings and variability to modulate a base dose.
  - Encapsulated in a class that can later be replaced by trained ML models (e.g. gradient boosting, RNNs, or multi-modal transformers).
- `services/ml/preprocessing.py` centralizes feature engineering and normalization utilities to:
  - Keep the API layer agnostic to representation details.
  - Make it easy to inject more sophisticated time-series or multi-modal processing.

## Development Notes

- SQLAlchemy is configured with a local SQLite database at `./data/app.db`.
- Alembic is included as a dependency for future migrations, but no migration scripts are generated by default.
- The codebase prefers:
  - **Explicit Pydantic models** for all request/response payloads.
  - **Thin API routes**, delegating business logic to `services/` and `db/` modules.
